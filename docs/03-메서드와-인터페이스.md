# 03 — 메서드와 인터페이스

Go에는 클래스도, 상속도 없다. 대신 **메서드**와 **인터페이스** 두 가지로 다 한다.

## 메서드

함수 이름 앞에 **수신자(receiver)** 를 붙이면 메서드가 된다.

```go
func (m Monitor) Timeout() time.Duration {
    return time.Duration(m.TimeoutMS) * time.Millisecond
}
```

`(m Monitor)` 가 수신자다. TS의 `this` 에 해당하지만 **이름을 직접 정한다.**
관례상 타입 이름의 첫 글자 한두 자를 쓴다 (`m`, `c`, `r`).

호출은 똑같다.
```go
ctx, cancel := context.WithTimeout(ctx, m.Timeout())
```

### 값 수신자 vs 포인터 수신자

이게 제일 중요한 선택이다.

```go
func (m Monitor) Timeout() time.Duration          // 값 — 복사본을 받는다
func (c *Config) applyDefaultsAndValidate() error // 포인터 — 원본을 받는다
```

**포인터 수신자를 써야 하는 경우:**

1. **수신자를 수정해야 할 때.** 값 수신자로 필드를 바꾸면 복사본만 바뀌고
   원본은 그대로다. 컴파일 에러도 안 나서 조용히 틀린다.
   ```go
   func (c *Config) applyDefaultsAndValidate() error {
       c.Workers = defaultWorkers   // 포인터라서 진짜로 바뀐다
   }
   ```
2. **구조체가 크고 복사 비용이 아까울 때.**
3. **타입에 이미 포인터 수신자 메서드가 하나라도 있을 때.**
   한 타입의 메서드는 값/포인터 중 하나로 통일하는 게 관례다.

`Monitor` 의 `Timeout`, `Interval`, `IsEnabled` 는 전부 읽기만 해서 값 수신자다.

### 호출할 때는 Go가 알아서 맞춰준다

```go
m := Monitor{...}
m.Timeout()      // 값 메서드 — 그대로

c := Config{...}
c.applyDefaults()   // Go가 (&c).applyDefaults() 로 바꿔준다
```

주소를 얻을 수 있는 값이면 `&` 를 자동으로 붙여준다. 다만
**맵의 원소나 함수 반환값처럼 주소를 얻을 수 없는 것**에는 안 된다.

### 어떤 타입에든 붙일 수 있다

메서드는 구조체 전용이 아니다. 내가 정의한 타입이면 뭐든 된다.

```go
type Duration int64
func (d Duration) String() string { ... }
```

단, **다른 패키지의 타입에는 못 붙인다.** `time.Duration` 에 내 메서드를
추가하려면 `type MyDur time.Duration` 처럼 새 타입을 만들어야 한다.

## 인터페이스

**메서드 목록**이다. "이 메서드들을 가진 무엇이든 받는다"는 뜻.

```go
type Notifier interface {
    Notify(ctx context.Context, ev Event) error
    Name() string
}
```
→ 스펙 M3에서 쓸 인터페이스

### 암묵적 구현 — Go의 핵심 설계

TS/Java의 `implements` 같은 선언이 **없다.**
메서드 시그니처만 맞으면 **자동으로** 그 인터페이스를 만족한다.

```go
type DiscordNotifier struct{ WebhookURL string }

func (d *DiscordNotifier) Notify(ctx context.Context, ev Event) error { ... }
func (d *DiscordNotifier) Name() string { return "discord" }

// 어디에도 "implements Notifier" 라고 안 썼지만
var n Notifier = &DiscordNotifier{}   // 된다
```

이게 왜 좋냐면 — **인터페이스를 쓰는 쪽에서 정의할 수 있다.**
구현체가 인터페이스를 미리 알 필요가 없다.
그래서 Go에서는 인터페이스를 **소비하는 패키지**에 두는 게 관례다.

### 인터페이스는 작을수록 좋다

표준 라이브러리의 대표 인터페이스들은 메서드가 하나뿐이다.

```go
type Reader interface { Read(p []byte) (n int, err error) }
type Writer interface { Write(p []byte) (n int, err error) }
type Stringer interface { String() string }
type error interface { Error() string }
```

`io.Reader` 하나 덕분에 파일, 네트워크 연결, 메모리 버퍼, gzip 스트림이
전부 같은 함수에 들어간다. checker에서 쓴 이 코드가 그 예다.

```go
io.Copy(io.Discard, resp.Body)
//      ^^^^^^^^^^  ^^^^^^^^^^
//      Writer      Reader
```

`resp.Body` 가 뭔지 `io.Copy` 는 모른다. `Read` 만 있으면 된다.

> "**Accept interfaces, return structs**" — 인자는 인터페이스로 넓게 받고,
> 반환은 구체 타입으로. Go의 흔한 조언이다.

### error 도 그냥 인터페이스다

```go
type error interface {
    Error() string
}
```

`fmt.Errorf` 가 반환하는 것도 이 인터페이스를 만족하는 구조체일 뿐이다.
직접 만들 수도 있다.

```go
type CheckError struct {
    Monitor string
    Code    int
}

func (e *CheckError) Error() string {
    return fmt.Sprintf("%s: 상태 코드 %d", e.Monitor, e.Code)
}
```

### 타입 단언 (type assertion)

인터페이스 안에 든 **실제 타입**을 꺼낼 때 쓴다.

```go
transport := http.DefaultTransport.(*http.Transport).Clone()
```
→ `checker.go`

`http.DefaultTransport` 는 `http.RoundTripper` **인터페이스** 타입이지만
실제로는 `*http.Transport` 가 들어 있다. `Clone()` 이나 필드에 접근하려면
구체 타입으로 꺼내야 한다.

`.(T)` 는 틀리면 **panic**이다. 안전하게 하려면 두 값으로 받는다.

```go
t, ok := http.DefaultTransport.(*http.Transport)
if !ok { ... }
```

위 코드에서 단언을 그냥 쓴 건, 표준 라이브러리가 보장하는 값이라
틀리면 그건 정말로 프로그램이 죽어야 할 상황이기 때문이다.

### 타입 스위치

여러 타입을 분기할 때.

```go
switch v := err.(type) {
case *url.Error:
    ...
case *net.OpError:
    ...
default:
    ...
}
```

### nil 인터페이스의 함정

이건 Go에서 제일 악명 높은 함정이다.

```go
var p *CheckError = nil
var e error = p
e == nil          // false!! 
```

인터페이스는 **(타입, 값)** 한 쌍이다. 값이 nil이어도 *타입*이 들어 있으면
인터페이스 자체는 nil이 아니다. 그래서 **에러 타입 변수를 그대로 반환하지 말고**
`error` 타입으로 다루거나 명시적으로 `return nil` 을 쓴다.

```go
func bad() error {
    var e *CheckError    // nil
    if somethingWrong { e = &CheckError{...} }
    return e             // X 문제 없어도 err != nil 이 된다
}
```

## 구조체 임베딩 — 상속 대신

```go
type Base struct{ ID int }
type Derived struct {
    Base          // 필드명 없이 타입만 — 임베딩
    Name string
}

d := Derived{}
d.ID = 1          // Base 의 필드를 바로 쓸 수 있다 (d.Base.ID 와 같음)
```

메서드도 딸려 올라온다. 상속처럼 보이지만 **컴파일 타임 위임**일 뿐이고
다형성은 제공하지 않는다. 다형성이 필요하면 인터페이스를 쓴다.
