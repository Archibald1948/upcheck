# 12 — M4: 체크 타입 확장

## 스펙이 요구한 것

| 타입 | 검사 내용 |
|------|----------|
| `http` | 상태 코드, 응답 본문 키워드 매칭, 리다이렉트 정책 |
| `tcp` | 포트 연결 가능 여부 |
| `tls` | 인증서 만료까지 남은 일수 (30일 이하면 경고) |
| `dns` | 특정 레코드가 기대값으로 해석되는지 |

## 인터페이스로 나누기 — M3와 같은 패턴

M3에서 `Notifier` 로 알림 채널을 추상화한 것과 **똑같은 모양**이다.

```go
type Prober interface {
    Probe(ctx context.Context, m config.Monitor) Result
    Type() string
}
```

`Checker` 는 타입을 보고 알맞은 `Prober` 에게 넘기기만 한다.

```go
func New() *Checker {
    c := &Checker{probers: make(map[string]Prober)}
    c.register(newHTTPProber())
    c.register(newTCPProber())
    c.register(newTLSProber())
    c.register(newDNSProber())
    return c
}
```

```
internal/checker/
├── checker.go   Result · Prober 인터페이스 · 타입별 분배
├── http.go      상태 코드 · 본문 키워드 · 리다이렉트
├── tcp.go       포트 연결
├── tls.go       인증서 만료
└── dns.go       레코드 해석
```

**스케줄러와 collector 는 한 줄도 안 고쳤다.** `checker.Checker` 와
`checker.Result` 라는 공개 면이 그대로라서, 안쪽을 통째로 갈아끼워도
바깥이 모른다. 그게 인터페이스로 나눈 값이다.

### 공통 필드는 Checker 가 채운다

```go
func (c *Checker) Check(ctx context.Context, m config.Monitor) Result {
    res := Result{
        Monitor:   m.Name,
        Type:      m.Type,
        CheckedAt: time.Now().UTC(),
    }
    ctx, cancel := context.WithTimeout(ctx, m.Timeout())
    defer cancel()

    out := prober.Probe(ctx, m)
    res.OK, res.Latency, res.Err = out.OK, out.Latency, out.Err
    ...
}
```

타임아웃 설정, UTC 시각, 이름 채우기 같은 건 네 군데에서 반복할 일이 아니다.
`Prober` 구현체는 **자기가 아는 것만** 채우면 된다.

### Close 는 인터페이스에 넣지 않았다

```go
func (c *Checker) Close() {
    for _, p := range c.probers {
        if closer, ok := p.(interface{ Close() }); ok {
            closer.Close()
        }
    }
}
```

정리할 자원이 있는 건 `httpProber`(커넥션 풀)뿐이다.
`Prober` 에 `Close()` 를 넣으면 나머지 셋이 빈 메서드를 달아야 한다.

대신 **익명 인터페이스로 타입 단언**해서 "Close 를 가진 것만" 골라냈다.
`interface{ Close() }` 는 그 자리에서 만든 이름 없는 인터페이스다.
Go에서 선택적 기능(optional behavior)을 표현하는 흔한 방법이다.

## 타입별로 다른 것들

### tcp — 연결만 하고 바로 끊는다

```go
conn, err := p.dialer.DialContext(ctx, "tcp", m.Target)
...
conn.Close()
```

HTTP 를 안 하는 것(데이터베이스, 메시지 큐, SMTP)을 감시할 때 쓴다.
**연결을 붙잡고 있을 이유가 없다.** 안 닫으면 감시 대상 서버의
연결 수가 계속 늘어나서, 모니터링이 장애 원인이 된다.

`net.Dialer` 에 `Timeout` 을 걸지 않았다. `DialContext` 에 넘기는 ctx 가
이미 시한을 들고 있고, 그쪽이 셧다운 취소까지 함께 처리한다.
(`http.Client.Timeout` 을 안 쓴 것과 같은 이유 → [07](07-context.md))

포트는 **반드시** 적게 했다. 기본 포트를 짐작할 근거가 없다.

### tls — SNI 를 빠뜨리면 엉뚱한 인증서를 본다

```go
d := &tls.Dialer{
    NetDialer: p.dialer,
    Config: &tls.Config{
        ServerName: host,   // ← 이게 SNI
        RootCAs:    p.rootCAs,
    },
}
```

`ServerName` 을 안 넘기면 SNI 확장이 안 붙는다. 한 IP 에 여러 사이트가
올라가 있으면(요즘은 대부분 그렇다) 서버가 **기본 인증서**를 돌려준다.
그러면 엉뚱한 인증서의 만료일을 감시하게 된다.

인증서를 꺼내려면 구체 타입으로 단언해야 한다.

```go
tlsConn, ok := conn.(*tls.Conn)          // DialContext 는 net.Conn 을 준다
certs := tlsConn.ConnectionState().PeerCertificates
leaf := certs[0]                          // [0]이 서버 인증서, 뒤는 중간 CA 체인
```

**기본 검증을 끄지 않았다.** 그래서 "핸드셰이크 성공 = 인증서 유효"다.
만료·이름 불일치·체인 오류는 전부 `DialContext` 에서 에러로 온다.

### dns — HTTP 체크로는 안 잡히는 사고

DNS 가 엉뚱한 곳을 가리키는 사고는 서버가 멀쩡해도 서비스를 죽인다.
그런데 **HTTP 체크로는 안 잡힌다** — 엉뚱한 서버가 200 을 잘 돌려주기 때문이다.

```yaml
- name: Google DNS 레코드
  type: dns
  target: dns.google
  record: A
  expect: [8.8.8.8, 8.8.4.4]
```

기대값 중 **하나라도** 나오면 정상으로 본다.
라운드로빈 DNS 처럼 여러 값이 번갈아 나오는 경우를 받아주려는 것이다.

도메인 이름은 대소문자를 구분하지 않고 끝점(`.`)이 붙기도 한다.
설정에 `Example.COM` 이라고 적었다고 실패하면 안 된다.

```go
func containsFold(list []string, want string) bool {
    for _, v := range list {
        if strings.EqualFold(strings.TrimSuffix(v, "."), strings.TrimSuffix(want, ".")) {
            return true
        }
    }
    return false
}
```

특정 DNS 서버를 지정하려면 `PreferGo` 를 켜야 한다.

```go
func customResolver(addr string) *net.Resolver {
    return &net.Resolver{
        PreferGo: true,   // ← Go 자체 DNS 구현을 쓴다
        Dial: func(ctx context.Context, network, _ string) (net.Conn, error) {
            return (&net.Dialer{}).DialContext(ctx, network, addr)
        },
    }
}
```

`PreferGo` 없이는 OS 리졸버(cgo)가 쓰이는데, 그건 서버를 골라 쓸 방법이 없다.
`Dial` 함수가 세 번째 인자(원래 주소)를 버리고 우리가 지정한 서버로 보낸다.

## 경고 — 실패가 아닌 것

스펙의 "인증서 만료까지 남은 일수 (30일 이하면 경고)"를 어떻게 표현할지가
M4에서 제일 고민한 지점이다.

**실패(`OK=false`)로 만들면 안 된다.** 인증서가 30일 뒤에 만료돼도
서비스는 지금 멀쩡히 돌고 있다. 실패로 세면
- 업타임 통계가 망가진다 (99.9% 가 0% 로)
- M3 판정 엔진이 down 으로 확정해서 **한밤중에 가짜 장애 알림**이 간다

그래서 `Result` 에 별도 필드를 뒀다.

```go
type Result struct {
    OK      bool
    Err     error
    Warning string   // 실패는 아니지만 알아둘 것
    Detail  string   // 화면 표시용 한 줄 (DB에 저장 안 함)
}
```

```
[UP  ] tls   GitHub 인증서   31ms  만료 D-77 (2026-11-30)  ⚠ 인증서 만료까지 77일 ...
```

`-report` 에서는 업타임 표와 **따로** 모아 보여준다.
경고는 실패가 아니라 업타임 표에 안 나타나는데, 따로 안 보여주면
**인증서가 만료될 때까지 아무도 모른다.**

```
경고 1건
────────────────────────────────────────────
⚠  GitHub 인증서   인증서 만료까지 77일 (2026-11-30, 발급자 Sectigo ...)
```

> **남겨 둔 것**: 경고를 알림으로 보내지는 않는다. M3의 판정 엔진은
> up/down 두 상태만 다루는데, 여기에 warn 을 넣으면 상태 기계가
> 복잡해진다. 스펙 M4의 요구는 "경고"까지라 화면 표시로 끝냈다.
> 알림까지 보내려면 `Kind` 에 `KindWarn` 을 추가하고 별도 쿨다운을
> 두는 게 자연스럽다.

## 두 번째 마이그레이션

`warning` 과 `type` 컬럼이 필요해졌다. **00001 을 고치지 않고 새 파일을 만들었다.**

```sql
-- migrations/00002_check_warning.sql
-- +goose Up
ALTER TABLE checks ADD COLUMN warning TEXT NOT NULL DEFAULT '';
ALTER TABLE checks ADD COLUMN type TEXT NOT NULL DEFAULT 'http';
```

[09](09-데이터베이스.md)에 적어 둔 규칙 그대로다. 이미 적용된 마이그레이션은
`goose_db_version` 에 기록돼 있어서 고쳐도 다시 실행되지 않는다.
남의 DB 는 옛 스키마 그대로 남는다.

M2 시절에 만든 DB로 실제로 확인했다.

```
=== 마이그레이션 전 ===
적용된 버전: 0 1
checks 컬럼: id monitor_id checked_at ok status_code latency_ms error
기존 행 수: 12

=== upcheck 실행 ===

=== 마이그레이션 후 ===
적용된 버전: 0 1 2
checks 컬럼: id monitor_id checked_at ok status_code latency_ms error warning type
기존 행 수: 12 (보존됨)
```

`DEFAULT ''` 와 `DEFAULT 'http'` 를 준 덕분에 기존 12행이 그대로 살아 있다.
`NOT NULL` 컬럼을 기본값 없이 추가했다면 SQLite 가 거부했을 것이다.

## 설정 검증을 로드 시점으로

타입마다 `target` 모양이 다르다.

| 타입 | target | 비고 |
|------|--------|------|
| `http` | `https://example.com/health` | 스킴 필수 |
| `tcp` | `db.example:5432` | 포트 필수 |
| `tls` | `example.com` | 포트 생략 시 443, URL 로 적어도 받아줌 |
| `dns` | `example.com` | 호스트 이름만 |

**잘못된 설정은 첫 체크가 실패할 때가 아니라 로드 시점에 걸러야 한다.**
오타 하나 때문에 한밤중에 가짜 장애 알림을 받으면 곤란하다.

```go
case TypeTCP:
    if _, _, err := net.SplitHostPort(m.Target); err != nil {
        return fmt.Errorf("tcp 타입의 target 은 host:port 여야 한다 (%q)", m.Target)
    }
```

`tls` 는 흔한 실수를 에러 대신 받아준다. `https://example.com/path` 라고
적어도 `example.com:443` 으로 바꿔준다. 사람이 자연스럽게 적는 모양이라
거부하기보다 고쳐 주는 게 낫다는 판단이다.

## 부딪힌 것들

### 1. TLS 테스트가 엉뚱한 이유로 통과했다

만료된 인증서를 거부하는지 보는 테스트가 통과하긴 했는데,
실패 사유가 `EOF` 였다. **인증서 때문이 아니라 연결이 끊겨서** 실패한 것이다.

원인은 테스트 서버였다.

```go
conn, _ := ln.Accept()
conn.Close()          // ← 핸드셰이크 전에 닫아버렸다
```

`tls.Listen` 의 `Accept` 는 연결만 돌려주고 **핸드셰이크는 첫 Read/Write 때
지연 실행된다.** 바로 닫으면 클라이언트는 인증서를 받아보지도 못한다.

```go
go func(c net.Conn) {
    defer c.Close()
    if tc, ok := c.(*tls.Conn); ok {
        _ = tc.HandshakeContext(ctx)   // 핸드셰이크를 끝내고 닫는다
    }
}(conn)
```

고치니 제대로 된 실패 사유가 나왔다.

```
tls: failed to verify certificate: x509: certificate has expired or is not yet valid
```

**통과하는 테스트가 옳은 것을 보고 있는지는 따로 확인해야 한다.**
초록불이 곧 검증은 아니다.

### 2. 인증서 만료일을 테스트하려면 인증서를 만들어야 했다

실제 사이트를 쓰면 만료일이 언제 바뀔지 몰라 테스트가 불안정해진다.
그래서 테스트마다 유효기간을 정해 자체 서명 인증서를 만든다.

```go
func newTLSServer(t *testing.T, validFor time.Duration) (addr string, pool *x509.CertPool)
```

자체 서명이라 시스템 신뢰 저장소에는 없다. `tlsProber` 에
`rootCAs` 필드를 두어 테스트에서만 채우게 했다.

```go
type tlsProber struct {
    dialer  *net.Dialer
    rootCAs *x509.CertPool   // nil 이면 시스템 기본값. 운영에서는 항상 nil.
}
```

테스트를 위한 이음새(seam)를 코드에 두는 건 보통 냄새지만,
여기서는 **그게 없으면 인증서 검증 자체를 테스트할 수 없다.**
`nil` 이 곧 운영 동작이라 실수로 다르게 돌 여지도 없다.

### 3. tcp/dns 에 "상태 코드 0" 이 찍혔다

`printResult` 가 늘 `StatusCode` 를 찍고 있었다. http 말고는 그런 개념이 없어서
`0` 이 나왔고, 읽는 사람은 이게 실패인지 헷갈린다.

`Result.Detail` 을 두고 각 Prober 가 자기에게 맞는 한 줄을 채우게 했다.

```
[UP  ] tcp   Google DNS (TCP)     67ms  연결됨
[UP  ] tls   GitHub 인증서          17ms  만료 D-77 (2026-11-30)
[UP  ] dns   Google DNS 레코드       1ms  A 8.8.4.4 8.8.8.8
```

`Detail` 은 화면 표시 전용이라 DB에 저장하지 않는다.
저장할 값(`ok`, `latency_ms`, `error`, `warning`)과 보여줄 값은 다르다.

## 스펙 요구사항 점검

| 요구 | 상태 |
|------|------|
| `http` 상태 코드 · 키워드 · 리다이렉트 | M0부터 있던 것을 `httpProber` 로 옮김 |
| `tcp` 포트 연결 가능 여부 | `tcpProber` — 연결 후 즉시 닫음 |
| `tls` 인증서 만료 남은 일수 (30일 이하 경고) | `tlsProber` — 기본 `cert_warn_days: 30` |
| `dns` 레코드가 기대값으로 해석되는지 | `dnsProber` — A/AAAA/CNAME/TXT/MX/NS |
| 타입 추가가 쉬울 것 | `Prober` 구현 + `New()` 에 한 줄 |
| `go test -race ./...` | 통과 |
