# 01 — 기초 문법

TypeScript를 안다는 전제로, **다른 점 위주로** 정리한다.

## 파일의 기본 골격

```go
package main            // 1. 이 파일이 속한 패키지 (모든 .go 파일 첫 줄)

import (                // 2. 쓸 패키지들
    "fmt"
    "time"
)

func main() { ... }     // 3. 선언들
```

세 가지 규칙이 처음엔 낯설다.

1. **세미콜론을 안 쓴다.** 컴파일러가 줄 끝에 자동으로 넣는다.
   그래서 여는 중괄호를 다음 줄로 내릴 수 없다 — 거기서 문장이 끝나버린다.
   ```go
   if x > 0 {      // O
   if x > 0
   {               // X — 컴파일 에러
   ```
2. **안 쓰는 import는 컴파일 에러다.** 경고가 아니라 에러다.
   안 쓰는 지역 변수도 마찬가지. 처음엔 짜증나지만 죽은 코드가 안 쌓인다.
3. **import 순서는 gofmt이 정리한다.** 표준 라이브러리 그룹, 외부 그룹 순으로
   빈 줄을 두고 나누는 게 관례다.

## 변수

```go
var name string = "upcheck"   // 정식
var name = "upcheck"          // 타입 추론
name := "upcheck"             // 짧은 선언 — 함수 안에서만 가능
var count int                 // 제로값(0)으로 초기화
```

`:=` 가 제일 많이 쓰이지만 **함수 바깥(패키지 레벨)에서는 못 쓴다.**
그래서 전역 상수/변수는 `var` 나 `const` 로 쓴다.

```go
const (
    defaultIntervalSec = 60
    defaultTimeoutMS   = 5000
)
```
→ `internal/config/config.go`

### 제로값 — Go에 `undefined`가 없는 이유

선언만 하고 값을 안 넣어도 **항상 정해진 초기값**이 들어간다. 쓰레기값이 없다.

| 타입 | 제로값 |
|------|--------|
| `int`, `float64` | `0` |
| `string` | `""` (빈 문자열, `null` 아님) |
| `bool` | `false` |
| 포인터, slice, map, channel, 함수, 인터페이스 | `nil` |
| struct | 모든 필드가 각자의 제로값 |

```go
var cfg Config                 // 모든 필드가 0/""/nil 인 Config
yaml.Unmarshal(data, &cfg)     // 여기에 값을 채워 넣는다
```
→ `internal/config/config.go` 의 `Load`

**제로값이 바로 쓸 만하게** 타입을 설계하는 게 Go 스타일이다.
예를 들어 `var wg sync.WaitGroup` 은 초기화 없이 바로 쓸 수 있다.

제로값에는 함정도 있다. `bool` 필드는 "false로 설정함"과 "설정 안 함"을
구분할 수 없다. 그래서 `Monitor.Enabled` 는 `*bool`(포인터)로 뒀다.
지정 안 하면 `nil` 이라서 "기본값 true" 를 줄 수 있다.

```go
func (m Monitor) IsEnabled() bool {
    return m.Enabled == nil || *m.Enabled
}
```

## 타입

```go
int    int8 int16 int32 int64
uint   uint8 ... uint64
float64 float32
bool
string
byte   // = uint8
rune   // = int32, 유니코드 코드포인트 하나
```

**암묵적 형변환이 전혀 없다.** `int` 와 `int64` 도 서로 안 섞인다.

```go
var ms int = 5000
var d time.Duration = ms                        // X 컴파일 에러
var d time.Duration = time.Duration(ms)          // O 명시적 변환
```

`time.Duration` 은 사실 `int64` 에 이름만 붙인 타입이다(나노초 단위).
그래서 이렇게 쓴다.

```go
func (m Monitor) Timeout() time.Duration {
    return time.Duration(m.TimeoutMS) * time.Millisecond
}
```

`time.Millisecond` 자체가 `Duration` 값(1000000)이라서 곱셈이 성립한다.
`5 * time.Second`, `90 * time.Second` 같은 표현이 자연스러운 이유다.

## 함수

```go
func Load(path string) (*Config, error) { ... }
func classifyErr(ctx context.Context, err error) error { ... }
func truncate(s string, n int) string { ... }
```

TS와 반대로 **타입이 이름 뒤에** 온다. 그리고 **여러 값을 반환**할 수 있다.

같은 타입이 이어지면 묶어 쓸 수 있다.
```go
func add(a, b int) int   // a int, b int 와 같음
```

### 에러는 마지막 반환값

Go에는 `try`/`catch` 가 없다. 실패할 수 있는 함수는 `error` 를 **같이 반환**한다.

```go
cfg, err := config.Load(*configPath)
if err != nil {
    return err
}
// 여기서부터 cfg 를 안심하고 쓴다
```

이 `if err != nil` 이 Go 코드의 절반처럼 보일 때가 있는데, 이게 Go의 선택이다.
"실패 경로가 코드에 항상 드러나 있다"는 쪽을 택한 것이다. 자세한 건 → [04-에러-처리.md](04-에러-처리.md)

### 이름 있는 반환값과 `_`

안 쓰는 반환값은 `_` 로 버린다. 안 그러면 "선언했는데 안 씀" 에러가 난다.

```go
_, _ = io.Copy(io.Discard, resp.Body)   // 결과를 일부러 무시
```
→ `internal/checker/checker.go`. 여기선 "본문을 비우는 것"만이 목적이고
읽은 바이트 수나 에러는 필요 없어서 둘 다 버린다.
`_ =` 를 명시하면 "실수로 빠뜨린 게 아니라 의도적으로 무시했다"는 신호가 된다.

## 제어문

### if

괄호가 없고 중괄호는 필수다.

```go
if res.OK {
    upCount++
}
```

**if 안에서 변수를 선언**할 수 있다. 그 변수는 if/else 블록 안에서만 산다.

```go
if err := cfg.applyDefaultsAndValidate(); err != nil {
    return nil, err
}
// 여기서 err 는 존재하지 않는다 — 스코프를 좁게 유지하는 Go 관용구
```

### for — 반복문은 이것 하나뿐

`while`, `do-while`, `foreach` 가 전부 `for` 다.

```go
for i := 0; i < 10; i++ { }        // 일반
for x < 10 { }                     // while
for { }                            // 무한 루프
for i, v := range slice { }        // 순회
for k, v := range myMap { }        // 맵 (순서는 매번 랜덤!)
for range 5 { }                    // Go 1.22+ : 5번 반복
```

`range` 의 두 번째 변수는 **값의 복사본**이다. 고쳐도 원본에 반영되지 않는다.

```go
for _, m := range c.Monitors {
    m.TimeoutMS = 5000          // 복사본만 바뀜. 원본은 그대로!
}

for i := range c.Monitors {
    c.Monitors[i].TimeoutMS = 5000   // 이렇게 해야 원본이 바뀐다
}
```
→ `config.go` 의 `applyDefaultsAndValidate` 가 `for i := range` 를 쓰는 이유가 이것이다.

### switch

`break` 를 안 써도 된다. 자동으로 멈춘다(fallthrough 가 기본이 아님).

```go
switch ctx.Err() {
case context.DeadlineExceeded:
    return fmt.Errorf("타임아웃")
case context.Canceled:
    return fmt.Errorf("취소됨(종료 중)")
}
```
→ `checker.go` 의 `classifyErr`

조건식 없는 switch는 긴 if-else 체인을 대신한다.

```go
switch {
case n < 0:   return "음수"
case n == 0:  return "영"
default:      return "양수"
}
```

## 포인터

C와 달리 **포인터 연산이 없다.** 주소를 가리키는 것뿐이라 훨씬 안전하다.

```go
x := 42
p := &x        // &  : 주소를 얻는다   (*int 타입)
fmt.Println(*p) // * : 값을 꺼낸다     → 42
*p = 100        // 가리키는 값을 바꾼다
fmt.Println(x)  // → 100
```

### 언제 포인터를 쓰나

Go는 **모든 게 값 복사**다. 함수에 구조체를 넘기면 통째로 복사된다.
포인터를 쓰는 이유는 두 가지뿐이다.

1. **원본을 수정해야 할 때**
   ```go
   func (c *Config) applyDefaultsAndValidate() error {
       c.Workers = defaultWorkers   // 진짜 원본이 바뀐다
   }
   ```
   값 수신자 `(c Config)` 였다면 복사본만 고치고 끝났을 것이다. 조용히 틀린다.

2. **"값이 없음"을 표현해야 할 때**
   ```go
   Enabled *bool   // nil = 미지정, &true = 켬, &false = 끔
   ```

구조체가 크면 복사 비용 때문에 포인터를 쓰기도 하지만, 요즘 Go에서는
"수정하느냐"가 훨씬 중요한 기준이다.

### 필드 접근에는 `*`가 필요 없다

```go
m := &c.Monitors[i]
m.Name = "x"        // (*m).Name = "x" 와 같음 — Go가 알아서 풀어준다
```

### nil 포인터 역참조

`nil` 인 포인터를 `*p` 로 꺼내면 panic으로 프로그램이 죽는다.
그래서 `*bool` 같은 걸 쓸 땐 항상 nil 검사를 먼저 한다.

```go
return m.Enabled == nil || *m.Enabled
//     ^^^^^^^^^^^^^^^^ 이게 먼저. Go의 || 는 단축 평가라서
//                      nil 이면 오른쪽을 아예 실행하지 않는다
```

## defer

함수가 **끝날 때** 실행할 일을 예약한다. 어떻게 끝나든(return, panic) 실행된다.

```go
ctx, cancel := context.WithTimeout(ctx, m.Timeout())
defer cancel()                    // 함수 끝나면 반드시 정리

resp, err := c.client.Do(req)
if err != nil {
    return res                    // 여기로 빠져도 cancel() 은 실행된다
}
defer resp.Body.Close()
```

"리소스를 얻은 **바로 다음 줄**에 정리를 예약한다" — 이게 Go의 기본기다.
얻는 코드와 놓는 코드가 붙어 있어서 빠뜨리기 어렵다.

두 가지 규칙:
- 여러 개면 **역순**(LIFO)으로 실행된다.
- 인자는 **defer 하는 시점**에 평가되고, 실행만 나중에 된다.
  ```go
  start := time.Now()
  defer fmt.Println(time.Since(start))  // 함정: 지금 계산된 0초가 찍힌다
  defer func() { fmt.Println(time.Since(start)) }()  // 이렇게 해야 제대로
  ```

**반복문 안의 defer는 주의.** defer는 *함수* 끝에 실행되므로,
루프 안에서 defer 하면 루프가 다 끝날 때까지 쌓인다.
