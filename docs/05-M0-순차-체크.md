# 05 — M0: 순차 체크

## 목표

> YAML 설정에서 모니터 목록을 읽어 **순차적으로** HTTP GET → 콘솔 출력.
> 일부러 느리게 만들어 놓고, 모니터 50개면 얼마나 걸리는지 재보세요. M1의 동기가 됩니다.
> — `go-upcheck.md` M0

동시성을 **일부러 쓰지 않는다.** 먼저 아파봐야 M1의 설계가 납득이 된다.

## 만든 것

```

cmd/slowserver/main.go       일부러 느린 테스트 서버

```

## 측정 — 여기가 M0의 핵심

외부 사이트를 50번 때리면 민폐고 측정도 들쭉날쭉하다.
그래서 **지연 시간을 내가 정하는 로컬 서버**를 만들었다.

터미널 1:
```bash
go run ./cmd/slowserver -delay 200ms
```

터미널 2:
```bash
go run ./cmd/upcheck -config configs/bench-50.yaml
```

결과:

```
총 50개 중 50개 정상 · 소요 10.085s
모니터당 평균 202ms
```

### 이 숫자가 말하는 것

| | 순차 (M0) | 동시 (M1 목표) |
|---|---|---|
| 총 소요 | **10.085s** | ≈ 0.2s (가장 느린 하나) |
| 공식 | 모든 응답시간의 **합** | 가장 느린 하나 **+ 큐 대기** |
| 100개라면 | 20초 | 그대로 ≈ 0.2s |
| 500개라면 | 100초 | 그대로 ≈ 0.2s |

**진짜 문제는 총 시간이 아니라 주기를 못 지킨다는 것이다.**

`bench-50.yaml` 은 `interval_sec: 10` — 10초마다 한 번씩 재라는 뜻이다.
그런데 한 바퀴 도는 데 **10.085초**가 걸린다. 시작하자마자 이미 밀린다.

- 모니터 100개면 한 바퀴에 20초 → 10초 주기를 **2배 위반**
- 그동안 CPU는 놀고 있다. 응답을 **기다리기만** 하는 시간이다

이게 M1이 필요한 이유다. 동시성은 "빠르게 하려고" 쓰는 게 아니라
**"약속한 주기를 지키려고"** 쓴다.

### 왜 200ms가 현실적인 숫자인가

위 실행 로그에서 실제 사이트들이 126~518ms였다. 200ms는 과장이 아니라
평범한 HTTPS 엔드포인트의 응답시간이다. 해외 리전이면 더 걸린다.

## M0에서 이미 제대로 한 것들

M0이 "순차"라고 해서 대충 짠 건 아니다.
스펙 7절 **함정 목록**에 있는 것들은 처음부터 지켰다.

| 함정 | 어떻게 했나 | 위치 |
|------|------------|------|
| 매번 `&http.Client{}` 생성 | `Checker` 가 클라이언트 하나를 들고 재사용 | `checker.go` `New()` |
| 커넥션 풀 기본값이 작음 | `MaxIdleConnsPerHost` 를 2 → 10으로 | `checker.go` `New()` |
| 응답 본문을 안 닫음 | `defer resp.Body.Close()` + `io.Copy(io.Discard, ...)` | `checker.go` `Check()` |
| `Client.Timeout` 만 걸기 | `Client.Timeout` 을 **비우고** 요청마다 context 타임아웃 | `checker.go` |
| 로컬 시간대 저장 | `time.Now().UTC()` | `checker.go` |

`Client.Timeout` 을 일부러 안 쓴 게 중요하다. 그건 **취소가 안 된다.**
Ctrl+C를 눌러도 5초짜리 타임아웃이 끝날 때까지 기다려야 한다.
`http.NewRequestWithContext` + `context.WithTimeout` 을 쓰면
부모 context가 취소되는 순간 진행 중인 요청이 즉시 끊긴다.
M6의 "Ctrl+C 시 5초 내 종료" 완료 기준이 여기서 결정된다.

이미 Ctrl+C가 동작한다. `signal.NotifyContext` 로 SIGINT/SIGTERM을 받으면
취소되는 context를 만들고, 그걸 모든 체크에 넘겼기 때문이다.

```go
ctx, stop := signal.NotifyContext(context.Background(), syscall.SIGINT, syscall.SIGTERM)
defer stop()
```
